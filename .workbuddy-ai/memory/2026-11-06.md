"looked" more correct was the wrong one. Read the pixel dump before touching
the formula. Verified geometry (virtual px, `chev_left(x=12,y=14)`):

### strip_android_from_image.py fix

The strip script's `brand_in_gui()` was case-insensitive, which caught
lowercase `android` target-triple identifiers baked into the Zig-compiled
ELF's `.rodata` (at offsets ~1157321 and ~1309682 inside `./sbin/qeafinit`).
These are compiler platform identifiers (`android`, `eabi`, `musl`), not
user-visible brand strings. Changed `brand_in_gui()` from
`re.finditer(b"android", body, re.I)` to `re.finditer(b"Android", body)`
(case-sensitive) so the brand word `Android` (capital A) is still caught
and patched, while the platform identifier is left alone.

The strip regression test (`tests/strip_android_image_test.py`) was also
updated: the old assertion `plain.count(b"ANDROID!") == 2` no longer holds
because the new ELF doesn't embed `ANDROID!` in its body (the old one did
via a different code path). Replaced with a count-equality check plus an
explicit boot-header magic check at offset 0.

A real QEAF.CMD loop over the RAM FAT16 volume:
